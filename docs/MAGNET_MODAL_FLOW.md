# JPHOO 磁力弹窗：验证记录与实现策略

## 结论（2026-07-25）

对作品页 `https://www.jphoo.net/works/13259452493727751` 进行未登录的静态 HTTP 请求验证：

- HTTP 状态为 `200`，页面源码约 110 KB。
- 源码中有“磁力下载链接”按钮文字。
- 源码中没有 `magnet:` 链接。
- 源码中也没有点击弹窗后展示的磁力结果条目。

这表示磁力结果由按钮点击后通过 JavaScript 动态加载，而不是服务端直接写在作品页 HTML 中。

## 当前可靠做法

1. 使用 Playwright 启动已登录的 Edge。
2. 打开作品页。
3. 定位唯一的“磁力下载链接”按钮并点击。
4. 等待弹窗出现和列表加载完成。
5. 从弹窗内读取候选条目；仅在需要保存时读取对应磁力链接。

项目中的 `JphooScraper.get_magnet()` 已有浏览器页面与磁力元素的基础处理；后续可改成明确点击该按钮、等待弹窗、再解析弹窗内的磁力链接，避免把“静态页面没有磁力”误判为无资源。

## requests + BeautifulSoup 能做什么？

- 可以：扫描系列页、提取作品 URL、读取静态标题与元数据。
- 当前不能直接做：从作品页 HTML 取得动态弹窗中的磁力链接。

## 是否只能手动点击？

不一定。

- **立即可用：** Playwright 自动点击按钮。这与手动点击是同一个页面流程，但程序可以自动完成。
- **后续可优化：** 在浏览器开发者工具中找到按钮点击后实际请求的 API。若该接口不需要复杂验证，或能携带合法登录态/Cookie，再用 `requests` 调接口即可，无需每页打开浏览器。
- **不建议：** 仅凭静态 HTML 猜测磁力地址；本次实测页面并不提供该数据。

## 安全与数据边界

- 弹窗内可能标注“可能是错误链接”的候选项；程序应记录提示，不应自动下载。
- 磁力更新应比较 BTIH 哈希和文件大小，并把旧值、新值、来源与时间写入本地更新记录。

## 已定位的前端接口

前端脚本的 Axios 基址为：

```text
https://www.jphoo.net/prod-api
```

弹窗使用的请求为：

```text
GET /v2/dht/list
```

完整路径为：

```text
https://www.jphoo.net/prod-api/v2/dht/list
```

作品页传入的参数形状：

```text
pageNum=1
pageSize=12
dataId=<作品 ID>
keyword=<影片番号>
modId=<作品 modId>
order=dht
date=0
sort=
category=video
```

本次作品的公开页面数据可确定：`dataId=13259452493727751`、`keyword=BrazzersExxtra.26.07.06`、`modId=3`。

### 匿名接口验证

用以上参数进行未登录 HTTP 请求时，接口可达（HTTP 200），但返回业务错误 `code=500` 且没有条目；同一内容在已登录浏览器弹窗中能够加载。这表明该接口很可能依赖浏览器会话中的登录态、令牌或其它请求头。

程序不应把浏览器 Cookie 直接写入源码或日志。下一步若要实现纯 HTTP 调用，应在用户已授权的本地会话边界内，确认浏览器实际请求中需要的最小认证信息，并在运行时使用，不落盘展示敏感值。

## 程序实现约束（2026-07-25）

- 一个 JPHOO 扫描或更新任务只创建一个 Playwright 页面；系列扫描与逐影片磁力弹窗共用它，不会按影片批量新建标签页。
- 程序关闭浏览器上下文时，将本地会话保存至 `jphoo_storage_state.json`，下次运行自动加载；该文件已加入 `.gitignore`，不得提交或分享。
- 未登录时保留该浏览器页面 30 秒供手动登录，然后自动重试当前作品页面；不再要求在终端按回车。

## 三层提取策略（已实现）

1. 作品页直接存在 `magnet:` 链接时直接读取。
2. 若本地已缓存该作品的公开 API 参数，使用同一个 Playwright 浏览器上下文的 `context.request` 请求 `/prod-api/v2/dht/list`；浏览器会话留在内存中，不会被代码读取或打印。
3. API 不可用时，自动点击“磁力下载链接”按钮，捕获该按钮触发的 API 响应并解析；仍失败才从弹窗 DOM 读取磁力链接。

首次成功点击弹窗后，程序只缓存作品页与 API 请求 URL 的对应关系，用于后续同会话的批量请求；缓存不包含 Cookie、令牌、响应正文或账号信息。`jphoo_api_cache.json` 已加入 `.gitignore`。

用户已在 Yav 专用 Edge 中完成手动登录，并在真实作品页确认弹窗可加载。登录态只保存在本机 `jphoo_storage_state.json`，不会提交到 Git；第 3 层“自动点击弹窗”仍是可靠回退。

## 侧边浏览器实测（2026-07-25）

在 `https://www.jphoo.net/works/13259452493727751` 页面，按钮 `BrazzersExxtra.26.07.06磁力下载链接` 可被唯一定位并成功点击。约 2.5 秒后弹窗展示多条磁力结果和大小信息（包含 5.61GB、5.28GB 等）。因此“自动点击弹窗 → 读取结果”已得到真实页面验证。

## 最新批量验证（2026-07-26）

- 已登录的真实页面可打开 `BrazzersExxtra.26.07.01` 的磁力弹窗，并显示多条“复制磁力”候选项。
- 同一弹窗的候选项可能覆盖同日多部影片，不能把所有候选项都归给当前作品；程序按标题匹配归档，并把标题明显不同的候选项作为附带资源单独记录。
- JPHOO 系列列表必须使用 `pageNum` 参数；`page` 参数会重复返回第一页。大型系列受站点限流影响，列表扫描应分批运行，资料入库按来源网址去重，因此重新扫描不会重复建立影片。
