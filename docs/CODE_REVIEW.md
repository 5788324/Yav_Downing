# Yav 代码与功能链路审查

审查日期：2026-07-25

## 结论

主链路已具备可用性：来源管理 → 扫描作品页 → 提取磁力 → 写入 CSV/TXT/历史记录 → 检查更新 → 导出 Excel。JavDB 使用 `requests + BeautifulSoup`，JPHOO 使用已登录的 Playwright/Edge 页面。

本次审查已修复三个会影响使用的问题：

1. JPHOO 点击“磁力下载链接”后，原代码只检测到元素却没有再次转换为 `MagnetInfo`，导致可能返回空结果；现已在点击后立即解析并返回。
2. 双选项卡运行曾临时改写全局来源配置。若程序异常退出，磁盘上的配置可能只剩当前标签页；现改为使用任务内临时来源列表，不改写配置。
3. 扫描/更新在线程中直接弹出 Tk 提示框不安全；现通过主界面事件队列显示完成提示。

## 已验证

- `python -m py_compile scraper_app.py` 通过。
- JPHOO 系列扫描和逐影片检查传入同一个 Playwright 页面；不会为每部影片创建标签页。
- JPHOO 登录态保存文件与本地配置已在 `.gitignore` 中排除。
- Excel 导出字段为：影片名、原磁力链接、新磁力链接、更新时间、来源。

## 已知限制

- 网站的页面结构、反爬策略或登录规则变化时，JavDB/JPHOO 的解析器可能需要随之调整。
- JPHOO 的弹窗依赖已登录浏览器会话；公开 HTTP 接口目前不能替代浏览器流程，详见 `MAGNET_MODAL_FLOW.md`。
- “优先最大文件”依据页面展示的 GB/MB/KB 文本；页面没有提供大小时会按链接出现顺序处理。
- 当前未进行真实线上批量扫描验证，以免在审查阶段写入你的影片资料。首次使用建议先添加一个小系列做人工验收。

## 后续建议

1. 为 JavDB/JPHOO 的 HTML 解析添加离线样本测试。
2. 为网络请求增加有限次数重试与更清晰的错误分类。
3. 在添加来源时校验网址域名和保存目录，减少配置错误。

## Excel 主台账规则（已固定）

主台账文件为项目根目录的 `Yav_磁力台账.xlsx`，按系列分为独立工作表（例如 `Blacked`、`Wifey`），不依赖站点数量。固定列为：`序号、站点、系列、番号/ID、影片名、当前大小(GB)、网页地址、状态、初始磁力`。

- 新影片：在所属站点工作表新增一行。
- 新磁力：在同一影片行的右侧依次追加 `磁力更新 1`、`磁力更新 2` 等列，不覆盖初始磁力。
- 无磁力：扫描到但未找到磁力的影片也会新增一行，状态为“暂无磁力”或“暂无磁力（可手填）”；可直接手填“初始磁力”。TXT 旧文件保留，程序后续不再创建或合并 TXT；CSV 保留给程序处理，Excel 作为日常查看的主台账。

## 2026-07-25 JPHOO 同日多影片防误选

- 真实弹窗确认：一个作品页的磁力弹窗会同时出现同日另一部影片的多个版本，不能按“最大体积”直接选取。
- 现改为先以当前网页标题与每条磁力的文件名做词语匹配；只在匹配足够明确时，再从该影片的多个清晰度中选最大版本。
- 标题与当前影片高度匹配的版本归入当前影片；标题明显不同的同日条目会作为“弹窗附带资源”新增独立行，资源不丢失。
- 已用“Penthouse Or Bust / Cum And Get Me”双影片模拟测试：正确选中前者 5.61GB，单独给出后者时拒绝写入。

## JPHOO 实机复核（2026-07-26）

- 真实登录态下，作品页的磁力按钮和弹窗已验证可用；弹窗会返回多条候选资源。
- “扫描新影片”与“检查磁力更新”已拆开：前者先保证资料和封面可入库，后者才读取磁力，避免资料收录被登录态或弹窗失败阻塞。
- 已知边界：Brazzers Exxtra 这类约数千部作品的大系列容易触发 JPHOO 列表限流；已入库记录可安全保留，但全量列表断点重试仍是下一轮可靠性优化项，不能把一次部分扫描表述为全量完成。
