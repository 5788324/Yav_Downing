# Yav 私人资料库设计与迁移

## 定位

Yav 的主目标是管理个人浏览资料：完整影片目录、封面和结构化元数据优先；磁力只是影片的可追加资源版本。

## 数据归属

- 主数据：`目录\_Yav资源库\library.db`（SQLite）。
- 本地封面：`目录\_Yav资源库\covers\`。
- CSV/Excel：兼容导出物，不再承担演员、封面与手动资料的唯一存储职责。

数据库保留自动抓取字段和手动字段。页面展示优先取手动字段，自动扫描只更新自动字段。

## 迁移

首次启动或导入时，Yav 会读取每个来源目录内的 `_全部磁力汇总表.csv`：

- 按来源网址去重建立影片。
- 按 BTIH 哈希保存磁力版本历史。
- 无磁力行同样建立影片，封面状态为“待抓取”。
- 旧 TXT、CSV、Excel 不删除；Excel 继续保持每系列独立工作表。

## 补全封面与资料

资料馆窗口按系列运行“补全当前系列资料与封面”。JavDB 使用公开详情页 HTTP 解析；JPHOO 复用已登录的单个 Playwright 标签页。每部会尝试更新：标题、封面、演员、系列、发行商、发行日期。

封面无法下载不会中断任务；数据库会记录“无封面网址”或“下载失败”状态，可在后续补全时重试。

## 扩展站点

新增资源站时实现三层适配即可：系列列表、公开详情资料、磁力版本。资料库表结构不绑定 JavDB 或 JPHOO。
